## [0.0.2] - 2026-08-31

### 🛡 Security
- Fixed a permission bypass in the `search_link` override
  (`global_tree_view/api/tree_search.py`): the tree-node lookups used
  `frappe.get_all()`, which unconditionally forces `ignore_permissions=True`
  internally, silently discarding the `ignore_permissions` value the code
  computed from the request. Since this override replaces the global
  `frappe.desk.search.search_link` whitelisted method, any logged-in user
  could read every record (name and search fields) of any tree doctype
  site-wide — regardless of their role permissions or User Permission
  restrictions — through any Link field search. Switched both lookups to
  `frappe.get_list()`, which actually honors `ignore_permissions`.
- Added an explicit `frappe.has_permission(doctype, "read", throw=True)`
  guard before any tree-doctype data is fetched, so a user without read
  access gets a clear `PermissionError` instead of a silent empty/unfiltered
  result.
- `ignore_user_permissions` is now validated the same way core's
  `frappe.desk.search.search_widget` validates it (via
  `validate_ignore_user_permissions`, requiring `reference_doctype` +
  `link_fieldname`) instead of being trusted directly from the client.

### ✅ Tests
- Added `test_search_link_denies_user_without_read_permission` and
  `test_search_link_respects_user_permission_restriction` to
  `test_tree_search_setting.py`, covering both the doctype-level permission
  check and the row-level User Permission restriction.
